### 설계 결정과 그 이유

**별도 `TypingMode`를 만들지 않았다.** `memeOnly`와 같은 방식으로 스토어에
`scriptureId`·`scriptureKind`·`scriptureLine`만 뒀다. 모드를 하나 늘리면
`typing_results`·`typing_mode_counts`의 CHECK 제약과 `record_typing_result`까지
손대야 한다. 이벤트 중에 점수 경로를 건드릴 이유가 없다.

**보관함은 서버에 올리지 않는다.** 가사나 좋아하는 문단처럼 저작권이 걸린 글이
들어온다. 서버에 모으는 순간 우리가 배포자가 된다. 음원도 같은 이유다.

**음원만 IndexedDB에 둔다.** localStorage는 문자열만 담고 5MB 안팎이라 음원 하나도
들어가지 않는다. 상한은 40MB. 아무 글도 참조하지 않는 음원은 저장·삭제 때 자동으로
지운다 — 남겨두면 저장 할당량을 잡아먹고, 할당량을 넘기면 브라우저가
보관함(localStorage)까지 통째로 날릴 수 있다.

**종류는 저장할 때 직접 고른다.** 줄 수로 자동 판단하지 않는다. 한 줄짜리 가사도
가사로 남아야 하고, 줄 수는 사용자의 의도를 알려주지 않는다.
(종류가 없던 시절에 저장한 글은 읽을 때 줄 수로 메운다. 그때는 종류라는 개념이
없었으므로 무엇을 골라도 사용자의 뜻을 어기는 것이 아니다.)

**단문·장문은 저장된 글을 이어서 친다.** 한국어 단문·장문과 같은 감각이다. 한 글의
마지막 줄을 끝내면 다음 글의 첫 줄로, 마지막 글에서는 처음으로 돌아온다. 글이 하나면
그 안에서 순환한다. 그래서 워크스페이스는 글 하나가 아니라 **그 종류의 목록 전체**
(`scriptureItems`)를 들고 있다.

**가사는 한 곡을 끝까지 친다.** 곡 밖으로 나가지 않고, 마지막 줄에서 "필사를
마쳤습니다"를 띄운다.

**영상·음원은 뉴스 썸네일 칸(`#thumbnail-container`, 196×110)에 들어간다.** 그 칸은
이미 16:9이고 로고와의 정렬(로고 왼쪽 끝 ↔ 썸네일 오른쪽 끝이 문장 영역과 맞음)이
잡혀 있다. 따로 자리를 만들면 그 정렬이 깨진다. 떠 있는 PiP를 먼저 만들었다가 이
방식으로 교체했으므로 되돌리지 말 것.

## 절대 깨지 말아야 하는 것 세 가지

### 1) 필사로는 점수가 1점도 쌓이지 않는다

원문이 서버에 없어서 검산할 방법이 아예 없다. 같은 글자를 잔뜩 채워 넣으면 그대로
타수가 되어버린다. 방어선은 다섯 겹이다.

- `finishCurrentSentence`가 필사일 때 **맨 앞에서 return**한다. `recordResult`도
  `submitScore`도 지나가지 않으므로 `record_typing_result` 호출과 점수 outbox 적재가
  원천적으로 없다. **이 early return을 아래로 옮기지 말 것.**
- 문장에 `sentenceId`를 붙이지 않는다. 서버에 검산할 원문 자체가 없다.
- 세션 CNT(`sessionCounts[mode]`)도 올리지 않는다. 필사는 단문·장문·뉴스·단어 어디에도
  속하지 않아 어느 칸에 더해도 거짓이 된다(밈은 실제로 단문이라 셌다).
  그 자리에는 `LINE: n / m 줄`을 보여준다.
- `behaviorTracker`에 넣지 않는다(키 입력·조합·완료·붙여넣기 전부). 검증 불가능한
  글로 세션 통계를 흔들면 어뷰징 판정이 오히려 무뎌진다.
- 모드 섞임 차단: `setMode`·`toggleNewsSector`가 `scriptureId`를 지우고,
  `isWordMode`·`isNewsMode`는 필사 중이면 거짓이 된다.

**글을 이어서 쳐도 이 경로는 그대로다.** 몇 글을 지나도 점수는 0이다.

### 2) 클립보드는 타이핑 입력창만 잠근다

판정은 `typing-workspace.tsx`의 `isClipboardAllowed` 하나다.
**타이핑 카드(`#typing-tab`) 밖의 `input`·`textarea`에서만 클립보드를 허용한다.**

- 붙여넣기로 점수를 만들 수 있는 곳은 `#input` 하나뿐이다. 모든 문장이 그 textarea를
  지나고 점수는 그 값으로만 계산된다. 그래서 그 하나만 잠그면 충분하다.
- 우회로가 없는 이유: 다른 칸에 붙여 넣은 글은 `#input`에 넣을 수 없고, 거기서 다시
  복사해 와도 `#input`의 붙여넣기는 여전히 막혀 있다. 필사로는 점수가 안 쌓인다.
- `#input`만 지목하지 않고 카드 안쪽 전체를 막는 이유: 나중에 카드 안에 입력 요소가
  더 생겨도 자동으로 잠긴다.
- `Ctrl+V`를 keydown에서 막으면 `paste` 이벤트가 오기도 전에 끝나므로 단축키
  가로채기도 같은 판정을 쓴다. `Ctrl+A`·`Ctrl+C`까지 잠기면 긴 가사를 손볼 수 없다.
- `notePasteAttempt`(어뷰징 신호)는 **막힌 시도만** 센다.
- `#input`의 `drop`도 막았다. 클립보드를 막아도 선택한 글자를 끌어다 놓으면 그대로
  들어오던 구멍이었다. 이건 필사와 무관하게 원래 있던 문제다.

측정값 (프로덕션 빌드에서 이벤트를 직접 디스패치해 `defaultPrevented`를 확인):

| | paste | Ctrl+V | Ctrl+A | copy | 우클릭 | drop |
|---|---|---|---|---|---|---|
| 필사 제목·본문 | 허용 | 허용 | 허용 | 허용 | 허용 | 허용 |
| 타이핑 입력창 | 차단 | 차단 | 차단 | 차단 | 차단 | 차단 |

### 3) 원본 타입뉴스는 읽기 전용

`C:\Users\guswn\Desktop\⠀\타입뉴스`는 **운영 중**이다. 읽기만 한다.
필사 원본(`C:\Users\guswn\Documents\필사타입`)도 참고용이므로 수정하지 않는다.

## 줄 다이얼에서 두 번 걸린 곳 (다시 만지면 또 걸린다)

가사 문장 영역은 세 줄 다이얼이다. 가운데가 지금 칠 줄, 위가 방금 친 줄, 아래가 다음
줄이고, 줄이 넘어가면 트랙이 위로 올라간다. 단어 다이얼(`.word-dial`)을 세로로 세운
것으로 측정·FLIP 방식이 같다. 애니메이션이 **아예 안 나오던** 원인이 둘 있었다.

1. **측정 effect의 deps에 `sentence?.id`가 없으면 한 번도 측정되지 않는다.**
   다이얼은 `sentence`가 채워진 뒤에야 그려지는데, 그 렌더에서는
   `scriptureLine`·`scriptureLines`가 그대로여서 effect가 다시 돌지 않는다.
2. **다이얼을 그리는 조건에 `sentence`를 넣으면 안 된다.** `setScriptureLine`이
   `sentence`를 비우고 다음 틱에 새 줄을 넣으므로, 그 한 틱 동안 다이얼이 사라지고
   트랙 노드가 새로 생겨 "이전에 가운데 있던 줄"의 기준을 잃는다.

`#sentence`의 `key`도 `"line-dial"`로 고정해야 한다. 줄마다 remount되면 트랙이 새로
생긴다. `data-slot-key`는 원문 안의 **절대 줄 번호**다 — offset을 쓰면 한 줄 넘어갈
때마다 세 칸이 전부 새 노드가 되어 깜빡인다.

정지 상태 실측(151px 다이얼): done 422–472 / current 476–518 / upcoming 526–569,
세 칸 모두 다이얼 안, 현재 줄이 정중앙. 애니메이션은
`translate(-50%,-25px)` → `translate(-50%,-75px)` 260ms (정확히 한 줄 높이).

`save_my_preferences` 계열은 마이그레이션마다 **기존 함수의 이름을 바꾸고 바깥에 래퍼를
새로 만드는** 구조다. 그래서 "함수 이름 + 키 문자열"로 적용 여부를 판정하면 틀린다.
실제로 이 방식으로 `0035`·`0037`·`0039`가 미적용으로 잘못 나왔다.

지금 체인:

```
save_my_preferences                       (0037: customBackgroundPresets)
  └→ save_my_preferences_without_presets       (0041: fontFamily)
       └→ save_my_preferences_without_font_family  (본체: 화이트리스트, 0035·0038·0039)
```

⚠️ **잘못 판정하고 옛 마이그레이션을 다시 적용하면 최신 함수를 옛 버전으로 되돌린다.**
`create or replace`라 조용히 성공하고, 나중에 추가된 키(폰트·밈 등)가 사라진다.

올바른 판정 쿼리 — 어느 함수든 `true`가 하나 있으면 그 키는 지원된다:

```sql
select p.proname as "함수",
       (p.prosrc like '%newsTypingTarget%') as "뉴스설정_0035",
       (p.prosrc like '%customBackgroundPresets%') as "프리셋_0037",
       (p.prosrc like '%lagoon%') as "라군_0038",
       (p.prosrc like '%memeOnly%') as "밈_0039",
       (p.prosrc like '%fontFamily%') as "폰트_0041"
from pg_proc p
join pg_namespace n on n.oid = p.pronamespace
where n.nspname = 'public' and p.proname like 'save_my_preferences%'
order by p.proname;
```

`0037`의 실제 키는 `backgroundPresets`가 아니라 **`customBackgroundPresets`**다.

SQL을 클립보드로 담는 스크립트가 있다 (프로젝트 폴더에서 실행):

```powershell
.\scripts\copy-sql.ps1 -List
```

⚠️ 셸이 다른 폴더(`Documents\Keyxif` 등)에 있으면 `MODULE_NOT_FOUND`가 난다.

**마이그레이션은 운영자가 손으로 적용한다.** DB 연결 문자열이 없어서 DDL은 Supabase
SQL Editor에서 사람이 실행한다. 자동 적용을 시도하지 말 것.

## 환경 함정 (이번 세션에 실제로 시간을 뺏긴 것)

### 개발 서버가 낡은 CSS를 서빙한다 — 원인이 둘

기존 문서에 이미 한 번 적혀 있었고(`next dev` 중에 같은 `.next`로 `next build`를 돌림),
이번에 **두 번째 원인**을 확인했다.

**`globals.css`를 통째로 다시 쓰면(`[System.IO.File]::WriteAllText`) Turbopack이 파일
감시를 놓친다.** 그 뒤로는 편집이 아무리 들어가도 서버가 옛 CSS를 계속 내보낸다.
`Edit` 도구로 부분 수정하면 감시가 살아 있다.

증상 확인법 — 서버가 실제로 내보내는 CSS를 직접 읽는다:

```js
const href = [...document.styleSheets].find(s => s.href)?.href;
await (await fetch(href, { cache: "reload" })).text();
```

CSS를 만졌으면 **개발 서버를 재시작한 뒤** 확인할 것. 확실하게 보려면 프로덕션 빌드로
확인한다(`npm run build` 후 `npx next start -p 3003`).

> 지금 3001에 개발 서버가 하나 떠 있다(내가 띄운 것이 아니라 그대로 뒀다).
> **낡은 CSS를 물고 있으므로 한 번 재시작해야 필사 스타일이 보인다.**

### 브라우저 창이 화면에 안 보이면 애니메이션이 멈춘 채로 측정된다

인앱 브라우저 패널이 표시되지 않으면 프레임을 합성하지 않아 CSS 전환·애니메이션이
**첫 프레임에 얼어붙는다.** 그 상태로 `getBoundingClientRect`를 재면 엉뚱한 값이 나온다.

이번에 실제로 헷갈린 것:

- 썸네일이 196×110이 아니라 172×97로 나왔다 → `.thumbnail-wrapper`의
  `transform: scale(0.88)` 전환이 얼어 있었다(196×0.88 = 172).
- 사이드바가 화면 밖(left 1280)에 있는 것처럼 나왔다 → `slideInRight`가 `currentTime: 0`에
  멈춰 있었다. 기존 설정 패널도 똑같이 나오므로 내가 만든 문제가 아니었다.
- `body`에 `fadeInUp`의 `transform`이 남아 있으면 `position: fixed`의 기준이 body가 된다.

측정 전에 애니메이션을 끝내거나 취소한다:

```js
document.body.getAnimations().forEach(a => a.finish());
el.getAnimations().forEach(a => a.cancel());  // 최종 정지 위치를 볼 때
```

### 그 밖에

- **이 폴더는 git 저장소가 아니다.** `typenews-vercel`에 `.git`이 없어서 diff·revert가
  안 된다. 파일을 통째로 덮어쓰기 전에 반드시 읽을 것.
- **PowerShell 5.1은 `Get-Content -Raw`로 한글을 깨뜨린다.**
  `[System.IO.File]::ReadAllText($p, [System.Text.Encoding]::UTF8)`를 쓴다.
  쓸 때는 BOM 없는 UTF-8: `[System.Text.UTF8Encoding]::new($false)`.
  (단, 위에 적은 대로 CSS를 통째로 다시 쓰면 감시가 끊긴다.)
- **React 19의 `react-hooks/set-state-in-effect`.** effect 본문에서 곧바로 `setState`를
  부르면 lint가 막는다. 이 코드베이스는 `window.setTimeout(..., 0)`으로 한 틱 미루는
  방식을 쓴다. 이벤트 콜백 안에서 부르는 것은 괜찮다.
- **`supabase-js`의 `rpc()`는 예외를 던지지 않는다.** `{ data, error }`를 구조분해해서
  `error`를 반드시 로그로 남긴다. 이걸로 두 번 디버깅이 늦어졌다.
- **`PostgREST`는 1000행 상한이 있다.** `limit`을 키워도 조용히 잘리고, RPC에는
  `Range` 헤더가 먹지 않는다.
