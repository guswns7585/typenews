# 점수 체계

## 규칙

정확도 **80% 이상**으로 문장을 끝내면, **그 문장의 타수**만큼 점수를 받는다.

```
"열심히 살자"            = 13점
"happiness is important" = 20점
```

점수는 **문장의 속성**이다. 누가 언제 치든 같은 문장은 같은 점수를 준다. 사용자가 결과를 예측할 수 있고, 모드별 환산 계수 같은 설명이 필요 없다.

정확도가 80% 미만이면 0점이다. 부분 점수는 없다.

## 타수 세는 법

두벌식 키보드에서 **실제로 누르는 키의 수**를 센다. [keystrokes.ts](../../frontend/features/typing-engine/keystrokes.ts)

| 대상 | 타수 | 예 |
|---|---|---|
| 한글 음절 | 초성 + 중성 + 종성 | `열` = ㅇㅕㄹ = 3 |
| 겹받침 | 2타 | `값` = ㄱㅏㅂㅅ = 4 |
| 복합모음 | 2타 | `왜` = ㅇㅗㅐ = 3 |
| 쌍자음 (ㄲㄸㅃㅆㅉ) | 1타 | `까` = 2 — Shift 조합이라 한 번 |
| ㅒ, ㅖ | 1타 | `얘` = 2 |
| 영문·숫자·기호 | 1타 | `abc` = 3 |
| **공백** | **0타** | `가 나` = 4 |
| 무시 옵션으로 걸러진 글자 | 0타 | 문장부호 무시 시 `.`은 제외 |

## CPM과 점수는 다른 단위다

혼동하기 쉬운데 **의도적으로 다르다.**

| | 계산 | 이유 |
|---|---|---|
| **CPM** (속도 표시) | 한글 1글자 = 2타 고정 | 원본 타입뉴스와 같은 공식. Firebase에서 이관된 `max_cpm` 기록과 비교 가능해야 한다 |
| **점수** | 자모 단위 실제 타수 | 실제 노력에 비례해야 한다 |

CPM 공식을 바꾸면 이관된 사용자 최고 기록이 전부 무의미해진다. 그래서 건드리지 않는다.

## 서버 검증

클라이언트가 보낸 숫자는 위조될 수 있다. 완벽히 막을 수는 없으므로, **물리적으로 불가능한 값을 거르고 걸리면 탐지 신호를 남긴다.** ([abuse-detection.md](abuse-detection.md))

`record_typing_result`가 거절하는 조건:

| 룰 | 기준 | 근거 |
|---|---|---|
| `IMPLAUSIBLE_SCORE` | 한 문장 600타 초과 | 실측 최대가 장문 277타, 뉴스 본문 400타 안쪽 |
| `IMPLAUSIBLE_ELAPSED` | 0.5초 미만 또는 1시간 초과 | |
| `IMPOSSIBLE_SPEED` | 초당 20타 초과 | 분당 1200타. 한글로 환산하면 약 1080 CPM |
| `HOURLY_SCORE_CAP` | 1시간 누적 60,000점 초과 | 한글 단문 약 900 CPM을 1시간 무중단 유지해야 나오는 값 |

⚠️ **상한을 CPM으로 환산할 때 단위를 섞지 말 것.** 위 근거는 실제 문장 데이터로
다시 계산한 값이다. 자세한 환산표는
[CUTOVER-AUDIT.md](../../docs/CUTOVER-AUDIT.md)의 D3에 있다.

| 묶음 | 점수 ÷ CPM타 |
|---|---|
| 한글 단문·장문 | 1.07 ~ 1.11 |
| 영어 단문·장문 | 0.83 ~ 0.84 |

한글은 점수가 CPM보다 높고(자모를 낱개로 세므로), 영어는 낮다(공백이 CPM에서는
1타지만 점수에서는 0타라서).

**시간당 상한은 사람 기준으로 타이트하지만 일 상한이 없다.** 봇은 타이핑을 하지
않으므로 시간당 최대치를 24시간 유지해 하루 144만점까지 쌓을 수 있다. 사람이 열심히
쳐서 모으는 하루치(10만 안팎)와 10배 이상 벌어진다. `CUTOVER-AUDIT.md` D3 참고.

거절된 제출은 점수가 반영되지 않고 `abuse_signals`에 심각도 3으로 쌓인다.

## 마이그레이션 시 주의

`monthly_stats.typing_count`는 `0006`에서 **`score`로 이름이 바뀌었다.** 의미도 "완료한 문장 수"에서 "누적 타수"로 달라졌다.

- 과거 달의 데이터는 옛 기준(문장 수) 그대로 보존된다. 이미 마감된 달이라 다시 계산할 수 없다.
- 새 기준은 **커트오버 이후 시작되는 달부터** 적용된다.
- 그래서 **도메인 커트오버는 매월 1일 00:00(KST)에 해야 한다.** 월 중간에 넘기면 한 달 안에 두 기준이 섞여 랭킹이 불공정해진다.

`scripts/migrate_to_supabase.py`도 `score` 컬럼에 맞춰 수정되어 있다.
